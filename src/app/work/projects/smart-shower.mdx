## Design Process: Crafting the Flow

I built a fully interactive GUI prototype on the NXP board, focusing on features that blended user delight with technical feasibility. Here’s what I designed:

![Figma screen setup.](/images/projects/shower-gui/shower-screens.jpg)

1. **Starting a Shower:** Is one-tap launch the key? Do we need a "Welcome" screen? Do we need widgets? I created a bold shower presets on the home screen, triggering an outlets and temperature control. Testing showed 90% of users nailed it on the first try.
2. **Choosing a Preset:** Users craved personalization, so I designed a preset menu with saveable settings—temperature, flow, duration. A swipeable carousel on the 5” screen made picking presets a breeze, cutting selection time by 25%.
3. **Precise Water Temperature Control:** Comfort demanded precision. I crafted a sleek slider with 1-degree increments and a live temp readout. 50% of users reported a preference for small temperature changes in favor of the slider.
4. **Integrations:** Smart home fans wanted integrations with third-party subscriptions. I added controls for Spotify, playlists, and songs.

![Crank Storyboard dashboard.](/images/projects/shower-gui/crank-dashboard.png)

Figma components imported into Crank ensured consistency, while Lua scripting powered transitions like a temperature slider fade. Early usability tests on the board refined these interactions, retiring risks fast.

## Design System for Embedded Hardware

To wrap the project up, and ensure scalability, I've created a mini design system specifically for embedded prototyping. When creating a design system for embedded hardware, I learned three key takeaways:

![Embedded shower variables.](/images/projects/shower-gui/variables.png)

1. Components must be compatible with the target software on the specific hardware, ensuring seamless integration and functionality.
2. Components should be designed with flexibility in mind, allowing for easy testing and adaptation in remote settings. This is crucial for troubleshooting and maintaining the system's performance.
3. Remote Human-Machine Interface (HMI) collaboration is an essential aspect of the design system, enabling users to interact with the system and make adjustments, even from a distance.
