# Overview

Moen’s smart shower development program needed a solution that would enable product and design teams to quickly validate, test, and iterate shower features, GUI, and advanced interactions. Without specific expertise on the team, the project was stuck in limbo, so we decided to take the initiative and innovate within the design team. The solution, based on Crank, shortened firmware GUI development time by 30% in just five weeks.

![NXP MCIMX8ULP - SOM board, and 5” NXP BV screen.](/images/projects/shower-gui/nxp.jpeg)

How to overcome the challenge of efficiently prototyping and testing user interfaces on remote embedded hardware for HMI? This project addresed the problem of limited resoruces and functional issues in developing and testing such systems.

## Design System for Embedded Hardware

When creating a design system for embedded hardware, there are three key takeaways to consider:

1. Components must be compatible with the target software on the specific hardware, ensuring seamless integration and functionality.
2. Components should be designed with flexibility in mind, allowing for easy testing and adaptation in remote settings. This is crucial for troubleshooting and maintaining the system's performance.
3. Remote Human-Machine Interface (HMI) collaboration is an essential aspect of the design system, enabling users to interact with the system and make adjustments, even from a distance.

![Component list prepared for Crank Import.](/images/projects/shower-gui/prepping-for-crank.png)

### Importing Figma Components Into Crank Storyboard

After importing Figma components into Crank Storyboard, I created component events like state changes and seamless transitions between screens in embedded hardware. This contributed to a consistent design language while leveraging Crank Storyboard's powerful real-time interaction design capabilities.

- I’ve used embedded functionality within the Storyboard to create navigation and transitions.
- The significant breakthrough was adding custom transitions and events with Lua scripting, which was the final functionality needed for a working prototype.
