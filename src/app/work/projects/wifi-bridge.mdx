# Overview

Imagine managing padlocks in remote locations—warehouses, construction sites, or rental properties—where security is critical, but access is a logistical nightmare. You’re a facilities manager overseeing a remote warehouse. A contractor needs temporary access, but you’re miles away, and driving out to update a lock code isn’t an option. This was the reality for many Master Lock users—until we designed the Wi-Fi Bridge.

## The Challenge

Our team identified several key issues through research and customer feedback:

1. **Remote Access Struggles**: Warehouses, construction sites, and rental properties often lack supervised access management, relying on manual processes that compromise security and efficiency.
2. **Bluetooth Limitations**: While Bluetooth padlocks offered some advantages via the Vault Enterprise app, they lacked remote access and real-time notifications, requiring users to be within close range to manage them.
3. **Battery Life Concerns**: Adding Wi-Fi directly to padlocks was impractical—locks in remote locations like telecommunication towers might sit unused for months, and constant connectivity would drain their batteries.

## Research and Discovery

To address these challenges, I collaborated with product management, and external agency teams on a comprehensive research effort:

- **User Interviews**: Our agency partner interviewed current Master Lock Bluetooth device owners, revealing that 70% struggled with remote access management.
- **Internal Insights**: Feedback from sales and channel marketing highlighted business needs and user expectations.
- **Competitor Analysis**: We studied similar products to identify opportunities for differentiation.

![A slide from a research study done by Applause.](/images/projects/wifi-bridge/agency-study.jpg)

![Research findings in a table format.](/images/projects/wifi-bridge/research.jpg)

---

From this, we crafted four personas to guide our design:

1. **The Decision Maker**: Owners seeking to upgrade access control.
2. **The Operator**: Employees using locks to enter restricted areas.
3. **The Coordinator**: Facilities managers overseeing access and personnel.
4. **The Provisioner**: Staff responsible for setting up the bridge and connecting locks.

These personas shaped our approach. For instance, the Provisioner needed an intuitive onboarding process, which became a cornerstone of our design.

## Mapping the User Journey

I kicked things off by leading weekly working sessions with design, product, and engineering teams. These collaborative meetings were crucial for aligning everyone on user needs and brainstorming solutions.

We mapped out user flows, debated trade-offs, and prioritized features, ensuring our designs were both user-friendly and technically feasible:

- Provisioning the bridge and adding it to the system.
- Connecting the bridge to Wi-Fi.
- Managing bridges, padlocks and access.
- Receiving real-time notifications and history events management.
- Troubleshooting network issues.

These flows became the backbone of our high-fidelity wireframes and prototypes, which I designed for both mobile and web platforms.

## Design Process: Crafting the Experience

I created wireframes and prototypes for both mobile and web applicaitons, including the interface design and user flow with details for developers.

### Bridge Configuration Setup

A smooth Wi-Fi setup was essential. I designed an intuitive onboarding flow with step-by-step instructions and visual cues, making it easy for users to connect the bridge to their network. Guerrilla testing showed an average configuration time of under 2 minutes, a win for both novice and experienced users.

For the Master Lock Wi-Fi Bridge, I designed an onboarding process that guided users through connecting the bridge to their Wi-Fi network, ensuring a smooth experience on both mobile and web platforms.

**Mobile**: I created an intuitive flow with step-by-step instructions and visual cues (like progress indicators), making it easy for users to set up the bridge using their smartphone.

![Full wifi bridge mobile configuration wireflow.](/images/projects/wifi-bridge/configuration-setup-mobile.jpg)

![Wireflow describing how to add bridge to the Enterprise app.](/images/projects/wifi-bridge/add-bridge-mobile.jpg)

<br />

**Web**: On the web platform, I adapted the flow to leverage the larger screen, adding interactive tooltips and a detailed status bar to enhance the experience for desktop users.

![Screenshots of the bridge setup screens in the Enterprise web app.](/images/projects/wifi-bridge/setup-web.jpg)

This approach ensured consistency across platforms while tailoring the design to each device’s strengths. For example, mobile users could quickly scan a QR code to start the process, while web users had a form with auto-fill options—both leading to the same seamless outcome.

### WiFi Status and Connection Strength

Connectivity hiccups were bound to happen, so I designed a “Connection Health” dashboard to give users real-time visibility and control. This feature displayed Wi-Fi strength and device status with clear, actionable error messages and troubleshooting steps—think “Weak Signal: Move closer to router.”

**Mobile**: I crafted a compact dashboard with bold icons (e.g., green check for “Connected,” red alert for “Disconnected”) and a tap-to-reveal troubleshooting guide, perfect for on-the-go fixes.

![Wireflow describing how to check bridge wifi status.](/images/projects/wifi-bridge/wifi-status.jpg)

<br />

**Web**: For desktop users, I expanded the dashboard into a detailed view with a signal strength graph and hoverable tooltips, leveraging the larger screen to offer deeper insights without clutter.
This dual approach ensured consistency while playing to each platform’s strengths—quick fixes on mobile, detailed diagnostics on web.

![Wireflow describing how to check bridge wifi status in the web app with details for developers.](/images/projects/wifi-bridge/wifi-status-web.jpg)

### Managing Bridges, Padlocks and Access

Property owners needed more than just connectivity—they craved real-time oversight and control over their locks, even from miles away. I designed the “Bridge Details” feature to deliver that power, enabling automatic updates (like lock settings or event history) whenever a lock was woken up, no phone required. It also allowed remote tweaks to configurations, security patches, and temporary access codes for users like contractors—all without stepping on-site.

**Mobile**: I created a “Bridge Details” screen with a clean overview of the most important features including location and connectivity, perfect for busy operators and provisioners on the move.

![Images of mobile bridge details screens.](/images/projects/wifi-bridge/bridge-details-mobile.jpg)

<br />

**Web**: On desktop, I built a robust control hub listing bridge status, firmware version, and access logs, with dropdowns for updating network settings or assigning temporary codes, ideal for detailed management tasks.

![Images of web bridge details screens.](/images/projects/wifi-bridge/bridge-details-web.jpg)

This unified design bridged the gap between real-time monitoring and remote administration, tailored to mobile’s speed and web’s depth.

## Impact and Reflections

Though the project didn’t launch due to the changing priorities, it earned praise from stakeholders. One product manager remarked, _“This is the most user-friendly interface we’ve seen for a complex product like this.”_ The experience taught me valuable lessons:

- **Iterative Design**: Regular testing uncovered and resolved usability issues early.
- **Collaboration**: Partnering with engineering and product teams aligned design with technical feasibility.
- **Strategic Thinking**: Updating the design system added long-term value beyond the immediate project.
